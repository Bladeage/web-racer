# Übergabe: Kart-Rennspiel im Browser (Three.js)

Stand: 02.11.2026. Planung im Chat abgeschlossen. Noch kein Repo, noch kein Code.

## Ziel

Ein Kart-Rennspiel im Stil von Mario Kart. Läuft im Browser. Öffentliches GitHub-Repo, Auslieferung über GitHub Pages. Zwei Spieler im Split-Screen an einem Rechner.

Arbeitsweise: tokensparend. Eine kleine Etappe pro Session. Kurze Erklärungen in einfachem Deutsch, Schritt für Schritt. Der Nutzer hat wenig Code-Praxis.

## Entscheidungen

| Thema | Entscheidung | Warum |
|---|---|---|
| Spielart | Mario-Kart-artig: Verfolgerkamera, feste Rundstrecke, Drift mit Mini-Turbo | Wunsch des Nutzers |
| Mehrspieler | 2 Spieler, Split-Screen | Wunsch des Nutzers |
| Steuerung | Erst nur Tastatur | Wunsch des Nutzers. Gamepad später |
| Grafik | Freie CC0-Modelle von Kenney für Karts und Deko | Spart Modell-Code und Tokens |
| Technik | Vanilla JS mit ES-Modulen, Three.js per Import-Map von jsDelivr, exakte Version pinnen | Kein Build-Schritt. GitHub Pages liefert die Dateien direkt aus |
| Physik | Eigene einfache Arcade-Physik, keine Physik-Bibliothek | Reicht für Karts auf flacher Strecke. Weniger Code, weniger Tuning |
| Strecke | Per Code aus einer Kurve (Mittellinie mit Kontrollpunkten) erzeugt | Kollision wird einfach: Abstand zur Mittellinie entscheidet über Straße, Gras, Wand |
| Kollision Kart/Kart | Kreis gegen Kreis | Einfach und ausreichend |
| Split-Screen | Ein Renderer, zwei Kameras, `setViewport` und `setScissor` | Keine Bibliothek nötig |

## Vorschläge, noch zu bestätigen

- Tastenbelegung (mit `event.code` unterscheiden):
  - Spieler 1: W A S D, Drift auf `ShiftLeft`
  - Spieler 2: Pfeiltasten, Drift auf `ShiftRight` oder `ControlRight`
- Split-Screen oben/unten (wie im Original-Vorbild). Alternative links/rechts.
- Lizenz des Repos: MIT.

## Bekannte Risiken

- Viele Tastaturen erkennen nicht beliebig viele gleichzeitig gedrückte Tasten. Mit zwei Spielern an einer Tastatur kann das Eingaben verschlucken. Früh testen.
- Split-Screen zeichnet die Szene zweimal pro Bild. Auf Leistung achten (wenig Licht, wenig Schatten, einfache Materialien).
- Welches Kenney-Paket passende Karts enthält, ist nicht geprüft (Kandidaten: Racing Kit, Car Kit, Toy Car Kit). Lizenz und Inhalt vor dem Einbau prüfen. Nur die benötigten GLB-Dateien ins Repo legen.
- Namen "Mario Kart" und "Micro Machines" sind geschützte Marken. Nicht im Namen, Titel oder in Dateien verwenden.

## Nächste Schritte (je Schritt eine Etappe)

1. **Grundgerüst:** Repo anlegen (public), `index.html` mit Import-Map, leere Three.js-Szene. GitHub Pages aktivieren (Branch `main`, Ordner `/`). Abnahme: Seite läuft online.
2. **Ein Kart fährt:** Kenney-Modell laden, Arcade-Physik, Verfolgerkamera, Steuerung Spieler 1. Abnahme: Kart fährt flüssig auf einer Fläche.
3. **Strecke:** Strecke aus Kurve, Gras bremst, Wand stoppt, Checkpoints, 3 Runden, Rundenzeit. Abnahme: Runde fahren und Zeit sehen.
4. **Split-Screen:** Spieler 2, zweite Kamera, Kollision Kart/Kart. Abnahme: Zwei Spieler fahren gleichzeitig.
5. **Drift und Mini-Turbo.** Abnahme: Drift halten, loslassen gibt Schub.
6. **Rennablauf:** Countdown, Ziel, Ergebnis, Neustart. Abnahme: Komplettes Rennen von Start bis Ergebnis.

Danach: KI-Gegner, Items, Gamepad, weitere Strecken.

## Lokal testen

ES-Module laufen nicht per Doppelklick auf `index.html`. Im Projektordner einen einfachen Server starten, zum Beispiel `python -m http.server 8080`, dann `http://localhost:8080` öffnen.

## Regeln für tokensparendes Arbeiten

- Eine Etappe pro Session, danach anhalten und berichten.
- Kleine Module. Nur die Dateien lesen, die die Etappe betrifft.
- Asset-Ordner von Kenney nicht komplett einlesen.
- Keine Bibliotheken ergänzen ohne Rückfrage.
